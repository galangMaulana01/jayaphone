# UX Review — Pengalaman Langsung Sebagai Pengguna (2026-08-07)

Metodologi: login sungguhan sebagai keenam role (owner, kepala_cabang, kasir, teknisi, kurir, influencer) di browser nyata (Playwright, bukan cek kode), menjalankan alur kerja beneran (isi form, klik tombol, buka modal), di dua ukuran layar (desktop 1440px dan mobile 390px — mendekati device sungguhan). Tujuannya bukan mencari parity dengan legacy (sudah selesai di `LEGACY_GAP_ANALYSIS.md`), tapi menilai "rasanya" dipakai sebagai user asli, termasuk hal-hal yang tidak akan ketahuan dari code review atau test otomatis.

Status server saat review: frontend `npm run start` + backend `phonejaya` lokal dengan seed data QA, database in-memory. 0 console error di seluruh halaman yang diuji di keenam role.

---

## Yang sudah bagus (tidak perlu tindakan)

- Navigasi terasa cepat — 600-1000ms per pindah halaman di seluruh role yang diuji.
- Halaman berbasis kartu (Karyawan, Data Service teknisi, Katalog Produk & Dashboard Influencer) beradaptasi sangat baik di layar HP — tombol besar, mudah di-tap, tidak ada elemen terpotong.
- Alur Input Transaksi (kasir, diuji di viewport 390px): pilih unit → cari customer (autocomplete + saldo poin muncul) → "Estimasi Poin Didapat" muncul live sebelum submit (GAP-008) — berjalan persis sesuai desain.
- Modal Detail Unit (GAP-001): breakdown margin owner-only tampil rapi dan benar; kasir tidak melihat data finansial.
- Modal Statistik Karyawan (GAP-007): preset tab + custom date + chart tren berjalan mulus, termasuk di layar HP.
- Chart Dashboard Influencer (GAP-011) rapi dan responsif di HP.
- Empty state di seluruh aplikasi konsisten memakai bahasa Indonesia yang jelas ("Belum ada data dalam periode ini", dll), bukan layar kosong.

## Temuan baru (di luar 12 gap yang sudah diperbaiki sebelumnya)

### UX-001 — Tabel data menyembunyikan tombol aksi utama di layar mobile, tanpa indikasi bisa digeser
- **Prioritas**: High (dampak nyata ke pekerjaan harian)
- **Halaman terdampak (dikonfirmasi langsung)**: `/stok` (owner), `/stok-kasir` (kasir), `/approval-cod` (kasir — tombol Approve/Reject), `/request-sparepart` (teknisi), `/kurir-dashboard` (kurir — tombol Accept/status, inti dari halaman ini).
- **Bukti**: di viewport 390px, kolom "Aksi" (selalu kolom paling kanan di semua tabel ini) berada di luar area yang terlihat. Dikonfirmasi lewat `scrollWidth` (808px) vs `clientWidth` (356px) pada `/stok-kasir` — tabel memang bisa digeser horizontal, tapi tidak ada gradient/shadow/teks yang memberi tahu user bahwa itu mungkin.
- **Dampak**: paling parah di **Dashboard Kurir** — kurir bekerja 100% dari HP di lapangan (bukan di depan komputer), dan tombol "Accept" untuk broadcast job baru ada di ujung kolom yang paling sulit dijangkau. Kasir dan teknisi juga berisiko sama saat menggunakan HP/tablet di konter.
- **Rencana**: buat kolom "Aksi" sticky di sisi kanan (selalu terlihat tanpa scroll) dan/atau tambahkan fade/shadow di tepi tabel sebagai sinyal visual "masih ada konten di kanan", diterapkan ke seluruh halaman tabel yang terdampak. **Belum dikerjakan — menunggu keputusan user, dicatat di sini per instruksi eksplisit ("catat dulu saja").**

### UX-002 — Sumbu-Y chart Dashboard menampilkan pecahan Rupiah tidak masuk akal saat data kosong
- **Prioritas**: Medium
- **Halaman**: `/dashboard`
- **Bukti**: filter ke cabang/periode tanpa transaksi (mis. "JYP2 — Jayaphone Cabang Dago") membuat sumbu-Y chart "Penjualan harian" menampilkan "Rp 0,1 / Rp 0,2 / Rp 0,3 ... Rp 1" — Chart.js auto-scale 0-1 dengan seluruh data bernilai 0, diformat lewat `formatRupiah` yang tidak dibuat untuk nilai pecahan.
- **Dampak**: owner yang meninjau cabang baru/sepi melihat tampilan yang terlihat rusak, alih-alih pesan kosong yang jelas seperti komponen lain di halaman yang sama (mis. "Belum ada transaksi pada periode ini" pada tabel transaksi terbaru).
- **Rencana**: saat seluruh titik data chart bernilai 0, tampilkan empty-state yang sama seperti komponen lain di halaman ini, bukan me-render chart dengan skala pecahan.

### UX-003 — "Battery Health: 0%" tampil literal padahal artinya "belum diisi"
- **Prioritas**: Low
- **Halaman**: `UnitDetailModal` (dipakai `/stok`, `/stok-kasir`)
- **Bukti**: backend (`app/schemas/unit.py:59`) punya komentar eksplisit `battery_health: int = 0 # opsional, 0 = tidak diisi`, tapi modal menampilkannya sebagai "0%" — terlihat seperti baterai benar-benar mati.
- **Catatan**: sudah ada identik di legacy (`index.html:2614` juga `${u.battery_health || 0}%`) — bukan regresi migrasi, tapi tetap membingungkan di kedua versi.
- **Rencana**: tampilkan "—" atau "Belum diisi" saat `battery_health === 0`, sama seperti pola yang sudah dipakai `getStockAgeInfo` untuk kasus tanggal kosong.

### UX-004 — Owner bisa "Pecat" akun miliknya sendiri dari kartu Karyawan
- **Prioritas**: Low-Medium (potensi self-lockout, tapi bukan regresi)
- **Halaman**: `/karyawan`
- **Bukti**: kondisi render tombol Pecat hanya `role === 'owner' && k.aktif` (identik di `index.html:2113` dan `karyawan/page.tsx`), tidak ada pengecualian untuk kartu milik diri sendiri. Backend (`cabang_service.py:pecat_karyawan`) juga tidak punya guard — akan menonaktifkan login owner sendiri tanpa UI pemulihan.
- **Catatan**: identik dengan legacy, bukan regresi migrasi.
- **Rencana**: sembunyikan tombol Pecat/Reset PW pada kartu milik user yang sedang login (`k.username === currentUser.username`), atau minimal tambahkan konfirmasi ekstra ("Ini akun kamu sendiri — yakin?"). Perbaikan backend (guard di level API) di luar cakupan sesi ini (read-only reference).

### UX-005 — Label tombol "Upload Video Umum" membungkus 3 baris di header mobile
- **Prioritas**: Low (kosmetik)
- **Halaman**: `/influencer-catalog`
- **Bukti**: tombol di pojok kanan atas terlalu sempit di viewport 390px sehingga teks "Upload Video Umum" pecah jadi 3 baris.
- **Rencana**: perpendek label di breakpoint mobile (mis. "Upload Umum") atau pindahkan ke bawah judul alih-alih sejajar.

### Observasi — bukan bug, tapi worth didiskusikan
- **"Set Kepala Cabang" selalu membuat akun baru** (minta Nama/Username/Password) alih-alih memilih dari karyawan `Kepala Cabang` yang sudah ada di cabang tersebut. Dikonfirmasi ini perilaku yang identik dan disengaja di legacy maupun kontrak backend saat ini (`assign_kepala_cabang` selalu membuat user baru & menonaktifkan yang lama) — bukan bug migrasi, tapi mungkin worth didiskusikan sebagai keputusan produk di masa depan jika ingin alur "promosikan karyawan yang sudah ada" tanpa reset kredensial.

## False alarm yang sempat dicurigai tapi ternyata bukan bug (dicatat untuk transparansi)
- Chart Dashboard sempat terlihat kosong total di screenshot pertama — ternyata hanya screenshot diambil sebelum animasi Chart.js selesai (masalah timing skrip pengujian, bukan aplikasi).
- Kolom "Kasir" menampilkan "bayu" (username) bukan "Bayu Saputra" (nama lengkap) di beberapa baris Transaksi/Laporan — ternyata itu data seed QA milik skrip scratchpad sesi ini (`run_local_backend.py`), bukan bug aplikasi; transaksi yang benar-benar dibuat lewat alur aplikasi (dikonfirmasi saat pengujian GAP-007/008) menyimpan nama lengkap dengan benar.
- Header sticky sempat terlihat "duplikat" pada satu screenshot fullPage — artefak cara Playwright men-stitch screenshot fullPage dengan elemen `position: sticky`, bukan rendering ganda sungguhan saat user scroll normal.

## Status tindak lanjut

Belum ada kode yang diubah untuk temuan UX-001 s.d. UX-005 di atas — sesuai instruksi eksplisit user untuk mencatat dulu tanpa mengeksekusi perbaikan pada sesi ini. Prioritas rekomendasi jika/ketika dikerjakan: UX-001 (High) → UX-002 (Medium) → UX-003/UX-004/UX-005 (Low).
